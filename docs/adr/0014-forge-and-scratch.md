# 0014. 実験室に工房と Python のスクラッチを置く

- 状態: 採用
- 日付: 2026-09-29

## 背景

実験室で、モデルを覗くだけでなく、手元で作り変えて比べたい。量子化（変わったビット数も）、蒸留、変換と合成、
枝刈りを試し、元のモデルと比べたい。用意した機能にないことも、自分でコードを書いて試したい。

## 決定

- **工房**: 量子化、変換、LoRA の焼き込み、合成、枝刈り、蒸留をエンジンで行い、できたモデルをアプリのフォルダ
  （`Application Support/com.taiyou.sundesk/Models`）に MLX の形式で置く。エンジンは起動時に `SUNDESK_MODELS_DIR` でこの場所を知り、
  モデルの一覧に加える
- **量子化**: MLX の本物の量子化（2〜8 ビット、層ごとの配分、重みごとの上書き）に加え、量子化してすぐ戻して保存する
  「真似る」量子化を用意する。本物にない 1 ビットや 7 ビット、3 値（1.58 ビット）の効き目を試せる。大きさは減らない
- **蒸留**: 先生の確率分布（温度つき）と生徒の分布の KL と、正解のトークンの交差エントロピーを混ぜた損失で学ぶ。
  16GB に収めるため、既定では生徒に LoRA を付けて学ぶ。先生と生徒を同時に載せるのは、このときだけの例外
- **評価**: 同じノート（パープレキシティ）と同じプロンプト（生成）で、いくつかのモデルを並べて比べる。速さ、大きさ、メモリも出す
- **スクラッチ**: エンジンの中で Python を実行する。載せたモデル、`mlx`、`numpy`、`matplotlib` を使え、ノートブックのように変数が残る。
  出力、表、図をアプリに流す。スクリプトは `Application Support/com.taiyou.sundesk/Scripts/*.py` に保存する
- **記録**: 作るたび、比べるたび、実行するたびに、実験の記録に残す

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| **エンジンの中で Python を動かす** | 載せたモデルをそのまま触れる。MLX と numpy がそろっている | 何でも実行できる（自分の Mac で、自分のコードだけを動かす前提。エンジンは 127.0.0.1 とトークンでしか受け付けない） |
| Jupyter を別に立てる | 慣れた道具 | モデルをもう一度載せることになり、16GB では重い。アプリから見えない |
| 用意した機能だけにする | 安全 | 「なんでも試したい」に応えられない |

## 結果

- 作ったモデルは大きい（1〜数 GB）。モデルのタブと評価の画面から消せる
- スクラッチのコードは、エンジンの MLX のスレッドで動く。長い処理は止めるボタン（接続を切る）で中断する
