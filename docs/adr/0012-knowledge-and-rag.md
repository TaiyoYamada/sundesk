# 0012. 知識は毎回まとめて作り直し、RAG は 3 つの検索を順位で組み合わせる

- 状態: 採用
- 日付: 2026-09-29

## 背景

フェーズ 2 と 3 で、ノートから知識グラフを作り、ノートを根拠に答える RAG を作る。
どちらも「ノートを区切った単位（チャンク）」を土台にするので、作り方と更新の仕方を一度に決めたい。

## 決定

- **チャンク**: ノートを見出し（レベル 3 まで）で区切り、長い節は段落の切れ目で分ける（`MarkdownChunker`）。
  出典として節まで示せるよう、見出しの階層と行番号を持つ
- **作り直し**: チャンク、埋め込み、知識グラフを、ボタンひとつでまとめて作り直す（`KnowledgeBuilder`）
  - 埋め込みは本文のハッシュで使い回し、変わったチャンクだけ計算し直す
  - 知識グラフはアルゴリズムで作るので速い。毎回全部作り直す
  - 作り直しはアプリに 1 つだけ走らせ、進み具合をすべてのウインドウに流す
- **保存**: Vault ごとの SwiftData（`KnowledgeStore`）。概念の線は整数 ID の表にし、使うときにメモリへ展開する。
  埋め込みは Float32 のバイト列で持ち、検索のときに行列に並べて Accelerate で内積をとる
- **検索**: 次の 3 つの順位を Reciprocal Rank Fusion でまとめる
  - 意味: ruri-v3 の埋め込み（エンジンが止まっていれば飛ばす）
  - 語: 2 文字ずつの組（bigram）の一致を、珍しい組ほど重く数える
  - 知識グラフ: 質問に出てくる概念と、その隣の概念が多く出るチャンク
- **回答**: 上位の節に番号を付けてシステムの指示に入れ、答えの中の `[1]` を出典として残す
- **モデル**: Apple のオンデバイスモデル（Foundation Models）と、エンジンの MLX のモデルから選べる

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| **3 つの検索を順位で組み合わせる** | 語の一致に強い検索と、意味の近さに強い検索の弱点を補い合う。点数の尺度をそろえなくてよい | 3 回探す |
| 埋め込みだけ | 単純 | 固有名詞や記号の一致に弱い |
| ノートを保存するたびに差分で更新する | 常に新しい | グラフの分析（PageRank など）は全体にかかるので、結局まとめて計算し直すことになる |

## 結果

- 知識は手で作り直す（知識グラフかチャットの画面のボタン）。ノートを書き換えても、作り直すまでは古いまま
- 検索の重みづけ（RRF の定数 60、1 つの検索から 20 件）は、使いながら見直す
