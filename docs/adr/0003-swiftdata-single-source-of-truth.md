# 0003. SwiftData を唯一の DB にし、エンジンは状態を持たない

- 状態: 採用
- 日付: 2026-09-29

## 背景

アプリ（Swift）とエンジン（Python）の 2 つのプロセスがある。どちらもデータを持つと、
正本が二か所になり、食い違いが起きる。

## 決定

- ノートの本文はファイル（study-artifact の Markdown）が正本
- それ以外（索引、チャンク、埋め込み、知識グラフ、チャット、実験の記録）は SwiftData に置く
- エンジンは状態を持たない。受け取った入力から計算した結果を返すだけで、保存はアプリが行う
- 埋め込みベクトルも SwiftData に置き、検索はメモリ上の総当たりで行う（数千〜1 万チャンク規模）
- 画像や Attention の行列などの大きなデータはファイルに置き、SwiftData にはパスだけを持つ

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| **SwiftData に一本化** | 正本が一か所。バックアップや削除が単純 | ベクトル DB の機能は自前で用意する |
| Python 側にも DB（SQLite、ベクトル DB）を持つ | Python の道具をそのまま使える | 同期が必要になり、壊れたときの原因が追いにくい |

## 結果

- エンジンはいつ再起動しても困らない
- 知識グラフの線は、リレーションでたどらずに整数 ID の表として持ち、計算時にメモリに展開する
