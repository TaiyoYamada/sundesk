# 0016. ~/Research と study-artifact を、コピーせずその場で読む

- 状態: 採用
- 日付: 2026-09-30

## 背景

研究ライブラリ（[0015](0015-research-library.md)）は見本（SampleLibrary）で作ったが、本物の研究のデータは別の場所にある。

- `~/Research`: `paper/` に論文の PDF、`experiment/` に git で管理している実験のリポジトリ（数 GB）。
  実験の結果の置き方は、プロジェクトごとに違う
- study-artifact: 学習と研究のノート（Markdown、500 本以上）。研究に関係するのはその一部

これらを sundesk に持ち込むとき、写すと二重管理になり、実験を回すたびに取り込み直す必要がある。

## 決定

- どちらも**コピーせず、その場で読む**。ライブラリの一番上に `Research/`、`study-artifact/` としてつなぐ（`VaultMount`）。
  変更は FSEvents で見張り、sundesk からは書き込まない（開くと閲覧だけで、保存しない）
- study-artifact は、研究に関係するフォルダ（最適化、量子アルゴリズム、研究、論文メモなど）と、
  研究のタグの付いた `_inbox` のノートだけをつなぐ。どこを読むかは設定で選べる
- `~/Research/paper/` の PDF は、sundesk 側に論文メモ（`Papers/<キー>/note.md`）を作り、`pdf` でその場所を指す
- `~/Research/experiment/` の実験は、決まった形を求めず、`config.json` か CSV のあるフォルダを 1 回の実行として自動で見つける。
  実行の画面は読むだけ（設定、所見、図、表の先頭）
- つないだ Markdown と論文の PDF は、知識グラフ、検索、チャットの出典にそのまま使う
- 見本（SampleLibrary）はテスト専用にし、アプリの設定からは外した

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| **その場で読む** | 二重管理にならない。実験を回すとすぐ見える | 読むだけ。~/Research の形が変わると見え方が変わる |
| アプリの中にコピー | ライブラリの形がそろう | 数 GB を二重に持つ。取り込み直しが要る |
| 結果だけコピー | 小さい | コードとの対応が切れる。取り込み直しが要る |

## 結果

- sundesk は、研究の資料を「持つ」場所から「まとめて読む」場所になった。自分のメモ（論文メモ、自分の実験、ノート）だけを sundesk に書く
- 実データでも、知識の作成は数分で終わる
- 実行の見つけ方は、シンボリックリンクと、notebooks/・docs/・paper/ などの中は探さない。
  うまく拾えないプロジェクトが出たら、プロジェクトに小さな設定ファイルを置いて補う（まだ作っていない）
