# 0013. 実験室は mlx-lm の計算を差し替えて覗き、画像生成は mflux を使う

- 状態: 採用
- 日付: 2026-09-29

## 背景

LLM の中を覗き（トークン、確率、Attention、logit lens、活性）、いじり（LoRA、steering）、
画像を生成する。どれも Python のエンジンで動かす（[ADR 0002](0002-swift-app-with-python-engine.md)）。

## 決定

- **覗く**: mlx-lm のモデルのうち、`embed_tokens`、`layers`、`norm` を持つもの（Llama、Qwen、Mistral など）に対応する
  - Attention の重みは高速な計算の中に隠れているので、指定した層だけ重みを明示的に計算し直す
  - logit lens、活性、steering は、層の繰り返しを自分で回し、途中の状態を取り出したり足したりする
  - 重い計算を避けるため、プロンプトは 512 トークンまでにする
- **LoRA**: mlx-lm の学習の仕組みを使い、ノートの本文をそのまま「続きを書く」形で学習する。1 割を検証に回す
- **画像生成**: mflux で FLUX.2 klein 4B と Z-Image Turbo を動かす
- **メモリ**: 大きいモデル（LLM か画像生成）は同時に 1 つだけ載せ、切り替えるときに前のものを外す。埋め込みモデルは別枠で載せたままにする
- **記録**: 実行するたびに、モデル、プロンプト、設定、結果の要約をアプリ全体の SwiftData（`LabStore`）に残す。
  重いデータ（Attention の行列など）は残さない。LoRA のアダプタと生成した画像は、アプリのデータフォルダに置き、パスだけを記録する
- **画面**: 実験室、モデル、画像生成をそれぞれタブで開く。グラフは Swift Charts と SwiftUI の Canvas で描く

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| **mlx-lm の計算を差し替える** | Hugging Face の新しいモデルがすぐ使える。Apple シリコンで速い | 構造の違うモデルには個別の対応が要る |
| TransformerLens / nnsight（PyTorch） | 覗く道具がそろっている | MPS では遅く、メモリも食う。MLX と二重にモデルを持つことになる |
| mlx-swift でアプリの中で動かす | Swift だけで完結する | モデルのクラスが内部に閉じていて、覗くには写して改変する必要がある |

## 結果

- 対応していない構造のモデルでは、覗く機能が 422 を返す。画面ではそのまま理由を出す
- 16GB では、LoRA は 0.6B〜1.7B、画像生成は 4bit の量子化が現実的
