# 0018. CLI と MCP サーバーは、ライブラリのファイルを直接開く

- 状態: 採用
- 日付: 2026-11-01

## 背景

Mac で常駐している別のアプリ（JobNeko の agentd）から、研究の担当の AI に文献を探させたり、足させたりしたい。
ターミナルや Claude Code からも、アプリを開かずに文献を入れたり探したりしたい。
そのためには、アプリの外から sundesk のライブラリを読み書きする入口が要る。

## 決定

- **Swift の CLI を 1 つ作る。** パッケージの実行ファイルのターゲット `SundeskCLI`（製品名 `sundesk-cli`）にし、
  `make install-cli` で `~/.local/bin/sundesk` に入れる。
  アプリの中（`Contents/MacOS`）には置かない。アプリ本体と同じ名前になり、大文字と小文字を区別しないファイルシステムでは並べられないため
- **MCP サーバーは、同じ CLI の `sundesk mcp` にする。** 標準入出力で待ち、公式の Swift SDK（modelcontextprotocol/swift-sdk）を使う。
  ツールの中身は CLI の命令と同じ（`LibraryAccess`）で、結果の JSON の形もそろえる
- **ライブラリのファイル（`library.store` と `Storage/`）を直接開き、アプリと同じ `LibraryInteractor` を通す。** アプリが起動していなくても使える
- **アプリへの知らせ**: Repository は保存のたびに分散通知（`DistributedNotificationCenter`、`com.taiyou.sundesk.libraryDidChange`）を送る。
  ほかのプロセスからの知らせを受けたら、画面に読み直させる。送り主にはプロセスの ID を付け、自分が送った知らせは無視する。
  2 つのプロセスで同じファイルを開き、片方の保存（題名の書き換え、コレクションへの追加、新しい文献）がもう片方の次の読み込みに出ることを確かめた
- **出す操作**: 探す、1 件を見る、コレクションの一覧、BibTeX（読むだけ）と、足す、コレクションに入れる（書き込む）。
  文献を消す、書誌情報を直す、コレクションを作る、消す操作は出さない。AI に取り返しのつかない操作をさせないため。
  MCP のツールには `readOnlyHint` などの注釈を付け、クライアントが書き込むツールにだけ承認を挟めるようにする
- **指し方**: 文献は引用キーで、コレクションは名前で指す。同じ名前のコレクションが 2 つ以上あれば、「親/子」の形で指してもらう
- **要約は出さない（当面）。** コマンドラインのプロセスから Foundation Models が動くかを、まだ確かめていない

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| ファイルを直接開く CLI と、その MCP サーバー（採用） | アプリが起動していなくても使える。ドメインとデータの層をそのまま使える | アプリに変更を知らせる仕組みが要る。2 つのプロセスが同時に書く |
| 起動中のアプリに XPC かソケットでつなぐ | 書くのはアプリだけになる | アプリが起動していないと使えない。受け口の分だけコードが増える |
| App Intents を `shortcuts run` で呼ぶ | OS の仕組みに乗る | 結果を JSON で受け取りにくい。アプリの起動に頼る |
| MCP サーバーを Streamable HTTP で常駐させる | 1 つのサーバーを何人ものクライアントで使える | 常駐の仕組み（launchd、ポート、認証）が増える。使うのは自分の Mac の中だけ |

## 結果

- Claude Code と JobNeko の agentd は、`sundesk mcp` を子のプロセスとして起動すればよい。
  agentd の中継（JobNeko の ADR 0047）は今は Streamable HTTP の URL だけを扱うので、標準入出力のサーバーをつなぐ種類を JobNeko の側に足す
- アプリで編集を保存する前（打ち終えてから 0.6 秒）に CLI が同じ文献を書き換えると、アプリの保存が後から上書きする。
  CLI が書くのは、新しい文献と、コレクションに入れることだけなので、当面はこのままにする
- 書誌情報の取得は、アプリと同じく doi.org、arXiv、Open Library、Crossref に行く
