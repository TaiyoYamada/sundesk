# 0006. エンジンとは 127.0.0.1 の HTTP で、起動ごとのトークンを付けて通信する

- 状態: 採用
- 日付: 2026-09-29

## 背景

アプリとエンジンは別プロセス（[0002](0002-swift-app-with-python-engine.md)）。
トークンの逐次送信や、Attention の行列のような大きなデータも送る必要がある。
当初の案は Unix ドメインソケット上の HTTP だった。

## 決定

- エンジンは FastAPI で作り、`127.0.0.1` の空いているポートで待ち受ける
- アプリは起動のたびにトークン（UUID）を作り、環境変数 `SUNDESK_ENGINE_TOKEN` でエンジンに渡す。
  リクエストには `Authorization: Bearer <トークン>` を付け、エンジンはそれを確かめる
- トークンをコマンドライン引数で渡さない（`ps` で見えてしまうため）
- 大きなテンソルは JSON にせず、生のバイト列と形の情報で送る（フェーズ 4 で詳細を決める）

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| Unix ドメインソケット上の HTTP | ファイルの権限で接続元を制限できる | URLSession が対応しておらず、HTTP クライアントを別に用意する必要がある |
| **127.0.0.1 の TCP + トークン** | URLSession（ストリーム、WebSocket）がそのまま使える。curl でも試せる | 同じ Mac の他のプロセスから接続はできる（トークンで拒否する） |
| 標準入出力で JSON-RPC | プロセスの寿命と通信路が一致する | 大きなデータやストリームを多重化しにくい |
| XPC | macOS 標準 | Python からは実用的でない |

## 結果

- エンジンを単独で起動して（`make engine`）、ブラウザや curl で試せる
- ポートは OS に選ばせるので、他のアプリと衝突しない
