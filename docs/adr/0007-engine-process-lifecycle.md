# 0007. エンジンは uv で起動し、アプリと寿命をそろえる

- 状態: 採用
- 日付: 2026-09-29

## 背景

エンジンは Python の仮想環境と依存関係が必要。また、アプリが終わったらエンジンも
終わらなければならない。開発中に、テストの強制終了でエンジンが 7 つ取り残される
不具合が実際に起きた。

## 決定

- エンジンは `uv run --project engine sundesk-engine` で起動する。uv が仮想環境の作成と
  依存関係の同期を済ませる
- プロセスの管理には swift-subprocess 1.0 を使う。止めるときは SIGTERM を送り、
  5 秒で終わらなければ強制終了する
- アプリは `applicationShouldTerminate` でエンジンを止め終えてから終了する
- アプリが強制終了やクラッシュで終わった場合に備え、アプリのプロセス ID を
  環境変数 `SUNDESK_PARENT_PID` で渡し、エンジンは 1 秒ごとにその生存を確かめる。
  いなくなっていたら自分に SIGTERM を送って終了する
- ユニットテストの実行中（`XCTestConfigurationFilePath` がある）と、
  UI テストの実行中（起動引数で無効化）は、エンジンを自動起動しない

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| **親のプロセス ID を見張る** | どんな終わり方でも確実に後を追える | 最大 1 秒ほど遅れて終了する |
| 標準入力が閉じたら終了する | OS の仕組みだけで済む | uv を挟むと標準入力の扱いが不確か。常にパイプを開けておく必要がある |
| 終了処理だけに頼る | 単純 | 強制終了やクラッシュのときに取り残される |

## 結果

- kill -9 でアプリを止めても、エンジンは残らないことを確認した
- アプリにエンジンの場所と uv の場所の設定が必要になった（設定画面で変えられる）
