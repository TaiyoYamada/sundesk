# 0002. 画面は Swift、AI と解析は Python のエンジンに分ける

- 状態: 採用
- 日付: 2026-09-29

## 背景

Hugging Face の新しいモデルを動かし、トークンの確率分布、Attention、各層の活性を覗き、
LoRA で学習し、画像を生成したい。日本語の形態素解析とグラフのアルゴリズムで
知識グラフも作る。使える言語は問わず、最適な技術を選ぶ方針。

## 決定

- 画面、SwiftData、可視化は Swift（SwiftUI、Metal）で作る
- LLM、画像生成、埋め込み、形態素解析、グラフの計算は Python のエンジン（`engine/`）に任せ、
  別プロセスとして動かす
- 自分専用のアプリなので App Sandbox は外す。study のノートやモデルのフォルダを自由に読み、
  エンジンを起動するため

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
|---|---|---|
| Swift のみ（mlx-swift-lm など） | 1 つの .app で完結する | 対応モデルが少ない（約 60 対 134）。Attention の取り出しにはモデルのコードの複製が要る。日本語の品詞解析やグラフのライブラリが乏しい |
| **Swift + Python** | mlx-lm、mflux、Sudachi、networkx などがそろう。新しいモデルに早く追いつける | プロセスが 2 つになる。Python の環境の管理が要る |

調査の詳細は docs/requirements.md の 7 章。

## 結果

- 新しいモデルや解析の手法を、Python の道具でそのまま試せる
- アプリとエンジンの間に通信の取り決めが必要になる（[0006](0006-engine-http-over-loopback.md)）
- エンジンの起動と停止を、アプリが面倒を見る必要がある（[0007](0007-engine-process-lifecycle.md)）
- メモリ 16GB では、大きいモデルを一度に一つしか載せられない。エンジン側で入れ替える
